## Critical (would give silently wrong results)
1. `evaluate.py`, local path: `LLM(..., enable_lora=True)` is set but no `LoRARequest` is passed to `generate`, so a tuned adapter is never applied. Take `--base-model` and optional `--adapter`, and pass `LoRARequest` when an adapter is given.
2. `evaluate.py`, local path: prompts are raw strings without the chat template. Use `LLM.chat(...)` (or `tokenizer.apply_chat_template(..., add_generation_prompt=True)`) with the same messages the FMAPI path sends.
3. One prompt everywhere: `prepare_data.py` writes "Extract events as JSON." while `task_adapter.py` has a different template. Build the prompt messages in one place (`task_adapter`), include the output schema and the verbatim-copy rule in it, and use it in data prep, SFT, GRPO, baselines and eval. Store `prompt` (messages without the assistant turn) and `completion` (the assistant turn) as separate columns so nothing ever leaks the answer into an eval prompt.
4. `rewards.gated_extraction_reward`: with conversational prompts TRL passes each completion as a list of messages (`[{"role": "assistant", "content": ...}]`), so `_parse` gets a list and every reward is 0. Accept both plain strings and message lists. Add a test.
5. `rewards.extraction_reward` validates the gold document with the same strict rules and returns 0 for every prediction when gold is invalid. That hides data problems. Validate gold once in `prepare_data.py` and fail loudly (or report and drop with counts in the data card). The reward should only validate the prediction. Add a test.
6. `train_grpo.py` mixes an Unsloth model with `peft_config`. With Unsloth, apply LoRA through `FastLanguageModel.get_peft_model` and do not pass `peft_config`. It must also start from the SFT result: accept `--init-adapter` (load the SFT LoRA and keep training it) or a merged SFT checkpoint path. Set an explicit learning rate (LoRA RL around 1e-5 to 5e-6; make it an argument) and `seed`.
7. `train_sft.py`: `dataset_text_field="messages"` is wrong for chat data. Use the prompt/completion columns with completion-only loss. Set learning rate (LoRA around 2e-4, argument), epochs, `seed`, and evaluate on the dev split each epoch.
8. `probe.py` reads `torch.cuda.max_memory_allocated()` in the parent process, so it always reports 0. Instead, add a small TrainerCallback shared by both training scripts that logs peak GPU memory and seconds per step to MLflow. The probe just runs the training script with `--max-steps 30` and then prints those metrics plus `completions/clipped_ratio` and `frac_reward_zero_std` from the run.
